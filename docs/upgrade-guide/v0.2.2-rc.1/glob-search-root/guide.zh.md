# 含斜杠的 glob 模式以搜索目录为基准

[English](guide.md) | 中文

## 变更

当 `glob` 收到显式 `path` 时，含 `/` 的模式相对于该目录匹配。此前，ripgrep 使用 Session 工作目录坐标中的路径匹配这些模式，可能漏掉已有文件，或者要求在两个参数中重复目录前缀。

不含 `/` 的模式仍在任意深度匹配文件名。未指定 `path` 的调用、`grep`、Session 工作目录以及返回路径的坐标均不变。限制与遍历规则见[文件系统搜索参考](../../../../packages/fs/tool-fs-search/README.zh.md)。

## 迁移

从含斜杠的模式中移除重复的搜索目录前缀。例如，要查找 `src/nested` 的直接子文件，将：

```json
{"pattern":"src/nested/*.ts","path":"src"}
```

替换为：

```json
{"pattern":"nested/*.ts","path":"src"}
```

需要限制深度时保留 `nested/*.ts`；只有需要递归匹配时才添加 `**/`。

`path` 指定目录。应传入文件的父目录，并在 `pattern` 中匹配文件名，而不是把文件本身作为 `path`。在 Windows 上，选择其他驱动器时请使用绝对目录；对于含斜杠的模式，`D:src` 这类跨驱动器的驱动器相对路径会被拒绝，不会借用宿主进程的各驱动器当前目录。

确认调用能找到预期深度的已知文件，并且仍排除更深层文件。返回路径保留现有坐标；搜索目录不会变成 Session 工作目录。在共址工作区中，后续文件系统调用应使用返回路径，而不是模式相对路径。
